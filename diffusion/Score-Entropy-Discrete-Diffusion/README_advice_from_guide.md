I think we can add the delete gate to a diffusion language model, but I would recommend implementing it first in SEDD rather than Block Diffusion. SEDD is much simpler to get running in practice. The paper can make it sound more complicated than it really is, but the codebase is fairly manageable. I mainly pointed you to Block Diffusion because it gives a more intuitive picture of how discrete diffusion works and the paper itself is more readable than the SEDD paper.

One important clarification: the concrete scores in SEDD are mainly an interpretation of the network outputs for the loss computation. I would not think of them as changing the overall delete-gate setup too much. The actual architecture is nearly identical to BERT. The basic approach should stay the same as what you did before: use soft deletion during training and hard deletion at inference, and use the intermediate-layer representation for deleted tokens, similar to the pre-deletion QA setup for MrBert. So the delete gate would fit into the model in essentially the same way. (Some of these concepts are more easily described using pictures, maybe we can take some time to go over this at our Wednesday meeting?)

In terms of sequence, I would keep the first step simple: first replicate the SEDD code and get it running end-to-end. Don’t try to pretrain the whole model from scratch yet. My understanding is that they use OpenWebText for pretraining, and what we would want eventually is more like continued pretraining to learn the delete gate, rather than full pretraining from zero. But before any of that, I’d focus on getting the code working and making sure you understand the training/inference pipeline.
